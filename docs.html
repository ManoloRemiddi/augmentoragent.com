Browser 0.1.32 · Architecture & install

The honest, technical picture: two pieces, one loopback pipe, your DSH as the runtime. Nothing below requires modifying DeepSeek Harness.

This guide covers the public Browser release, tested on Linux with Chromium. Looking for the native app? See Augmentor Agent Desktop or compare platform support.

ARCHITECTURE

┌─ Chromium (MV3 extension) ─────────────────────────────┐ │ side panel (chat UI, session browser, model picker, veil │ │ controls) │ service worker = chat UI + browser executor │ page overlay: frost veil + status pill (per tab) └────────────────────────────┬──────────────────────────┘ │ chrome.runtime.connectNative ▼ ┌────────────────────────────▼──────────────────────────┐ │ Node helper — pipe.mjs (the only process we own) │ dumb protocol pipe: re-frames native port traffic as │ ├─ POST /api/<method> unary calls │ ├─ WS /api/events.mux .host downlink frames │ └─ WS /api/augmentor plugin action channel └────────────────────────────┬──────────────────────────┘ │ loopback → passes trust fence ▼ ┌────────────────────────────▼──────────────────────────┐ │ DSH app, your running installation │ dsh-augmentor plugin (profile bundle stack) │ ├─ ctx.tools.register: browser_* │ ├─ webServer route: WS /api/augmentor │ └─ session lifecycle + settings card │ stock: agent loop · session store · model catalog │ approvals · /api + downlinks └───────────────────────────────────────────────────────┘

WHY IT’S THIS SHAPE

  • →DSH already exposes every method the extension needs (the model catalog, session.create/list/history, session.selectModel, session.cancel) over loopback /api.
  • →No second runtime: your DSH is the runtime, and the conversation is a real DSH session in the app’s own store.
  • →No patch: session.interrupt is retired in favour of stock session.cancel (Stop).
  • →The extension cannot dial /api directly (see the trust fence), so the native host is the pipe, and we already ship it.
The shape holds: everything needed is stock DSH. The pipe stays a dumb loopback wire (a few hundred lines of pipe.mjs); everything smart lives in the extension and the plugin.

The trust fence, settled

DSH has a built-in defense (not configurable from Augmentor) that refuses browser-originated requests on its API. Understanding it is why the pipe exists.

Host fence

Host must be loopback (127/8, ::1) or a declared trusted authority, applied to every request.

Cross-site fence

sec-fetch-site: cross-site is refused. Browsers attach this metadata; a Node process never does.

Origin fence

If an Origin is present, its host must equal the Host’s. chrome-extension://<id> never equals 127.0.0.1:3080 → refused.

Consequence: the extension’s service worker fails checks 2 and 3 on every channel. So it talks through a small Node process on loopback, the native-messaging host we ship, a dumb protocol pipe (pipe.mjs): SW ⇄ connectNative ⇄ Node helper ⇄ /api + downlinks + plugin WS. No second runtime anywhere.

Install Augmentor 0.2.11

The current Desktop and Browser project is https://github.com/ManoloRemiddi/augmentor-agent. The 0.2.11 security release fixes a WebSocket memory-exhaustion vulnerability. Browser 0.1.32 is historical and should no longer be installed.

Use the matching complete release

For Debian 13 amd64, use the complete download and guided installation prompt. It supplies matching Desktop, Browser, native host and plugins. Follow the current installation guide and verify SHA256SUMS before extraction.

The npm package dsh-augmentor@0.2.11 updates only the DSH plugin. It does not fix an older native host or desktop. Keep all components on the matching release.

Upgrade an existing installation

Preserve profiles, chats, credentials, memory and model settings. The fresh installer refuses existing installations; do not remove user data to bypass it. Follow the reviewed upgrade procedure, finish active tasks before restarting DSH, then reload the matching extension. Custom presets require a reviewed migration.

Recommended companion: Model Picker Augmented

Version 1.1.2 supports DSH 0.1.5-rc.1 and fixes the plugin-loading error about undefined settings. It adds model search, pins and visibility controls to DSH. Augmentor uses the same model curation. This companion is optional.

Install the package from its GitHub release:

dsh plugin --profile web add https://github.com/ManoloRemiddi/dsh-model-picker-augmented/releases/download/v1.1.2/dsh-model-picker-augmented-1.1.2.tgz

Restart DSH and reload its page. If you already linked this plugin from a local Git checkout, update that checkout to v1.1.2 instead of adding a second copy. Source and full instructions.

Install with your coding assistant

Use the current complete installation prompt. It points to the security-fixed 0.2.11 release and requires preservation of existing data.

DSH's local web login only connects your browser to DSH on your PC. Reopen the complete URL printed by dsh web if authentication is required. A configured local model can run offline once its software and model files are installed. Cloud models need their provider's credentials and internet; visiting online pages also requires internet.

FAQ

One running app per port. The pipe dials $DSH_AUGMENTOR_URL (default http://127.0.0.1:3080, set in the native host’s environment); the handshake reports which deployment it reached, and the panel’s “Open in DSH” follows the same endpoint.
The tool handler returns a readable “no browser client connected” result and never blocks the turn. Reconnect reopens the pipe and refetches the session baseline.
The public 0.2.11 complete release is on GitHub. Use its matching extension and native companion; dsh-augmentor@0.2.11 is also on npm for the DSH plugin. The extension is not currently distributed through a browser store.
